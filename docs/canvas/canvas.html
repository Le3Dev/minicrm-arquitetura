Canvas de Arquitetura — Mini CRM distribuído

PJBL Arquitetura de Software · Pedro Henrique Z. Costa · Lincoln Neto · Nicolas Tancon · Leandro Canha

Proposta de valor

  • CRM enxuto para equipes pequenas de vendas: carteira de clientes, interações, funil e indicadores.
  • Evolui o Mini CRM (Azure Static Web Apps + Functions) para uma arquitetura distribuída com microsserviços, BFF, microfrontends, eventos e serverless.

Partes interessadas

  • Vendedor (própria carteira)
  • Gerente de vendas (equipe)
  • Administrador (tudo, ranking)
  • Professor / avaliação do PJBL

Funcionalidades centrais

  • CRUD de clientes com exclusão lógica
  • Histórico de interações
  • Funil Prospecção → Fechado
  • Dashboard agregado
  • Cliente vira Ativo ao ganhar oportunidade

Componentes

  • Shell React (host) B
  • MF Clientes A
  • MF Oportunidades B
  • AWS API Gateway A
  • BFF Node.js B
  • MS Clientes — Java/MongoDB A
  • MS Oportunidades — Java/Azure SQL B
  • Azure Function — Java A
  • Service Bus — fila oportunidade-ganha A

Atributos de qualidade

  • Manutenibilidade: Clean Architecture + vertical slices verificadas por ArchUnit
  • Resiliência: eventos com retentativa, dead-letter e idempotência; agregação tolera fonte fora
  • Segurança: API key, throttling, segredos fora do código

Restrições técnicas

  • Front nunca chama microsserviço direto
  • Microsserviços não se chamam: integração por evento
  • Imagens no Docker Hub
  • Demonstração só com URLs da nuvem

Restrições de negócio

  • Somente camadas gratuitas (Atlas M0, Azure SQL free, Container Apps, Functions Flex, AWS Free)
  • Dupla, prazo 29/11/2026
  • Regras herdadas da SPEC do Mini CRM (RF03–RF33)

Tecnologias

  • Back-end: Java 21, Spring Boot 3.5, Spring Data MongoDB/JPA, Flyway, springdoc (Swagger), Azure Functions Java
  • Front: React 19, Vite, Module Federation · BFF: Node.js
  • Nuvem: Azure Container Apps, Functions, Service Bus, Azure SQL · MongoDB Atlas · AWS API Gateway · Vercel
  • Qualidade: JUnit 5, ArchUnit, Mockito, Vitest, GitHub Actions · Contratos: OpenAPI, AsyncAPI

Decisões principais

  • Dois bancos por domínio (MongoDB × Azure SQL)
  • Evento OportunidadeGanha para RF30
  • BFF calcula escopo (RF15)
  • Concorrência otimista (@Version)

Riscos e mitigação

  • Cold start (Container Apps / Azure SQL serverless) no vídeo → aquecer serviços antes de gravar
  • Evento perdido se o Service Bus falhar após gravar → padrão Outbox como evolução
  • Créditos da AWS expiram em 6 meses → usar somente durante a avaliação

Métricas de sucesso

  • CI verde em todos os serviços
  • Fluxo completo no vídeo: CRUD → evento → cliente Ativo → dashboard
